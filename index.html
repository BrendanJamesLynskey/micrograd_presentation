Part 1

What & Why

An autograd engine in a nutshell

What is an autograd engine?

Autograd = automatic differentiation. You write an ordinary numerical expression; the engine quietly records every operation as a graph, then computes the derivative of the final output with respect to every input — exactly and automatically.

Backpropagation is just reverse-mode autodiff: walk the graph backwards, applying the chain rule at each node.

Why it matters: training a neural net is repeatedly asking "how should I nudge each weight to reduce the loss?" — that nudge direction is the gradient.

from micrograd.engine import Value

a = Value(-4.0)
b = Value(2.0)
c = a + b
d = a * b + b**3
c += c + 1
c += 1 + c + (-a)
d += d * 2 + (b + a).relu()
d += 3 * d + (b - a).relu()
e = c - d
f = e**2
g = f / 2.0
g += 10.0 / f
print(f'{g.data:.4f}')  # 24.7041 (forward)
g.backward()
print(f'{a.grad:.4f}')  # 138.8338 (dg/da)
print(f'{b.grad:.4f}')  # 645.5773 (dg/db)

The expression graph

Every operation builds a node; arrows point from a result back to the operands that produced it.

This dynamically constructed DAG (directed acyclic graph) is the whole trick. Forward pass fills in .data; the backward pass fills in .grad for every node.

Why scalars, not tensors?

Real frameworks (PyTorch, JAX) operate on tensors — n-dimensional arrays — so a single op moves millions of numbers at once on a GPU.

micrograd deliberately works on single scalar values. One Value wraps one float.

The point is clarity. By stripping away tensors, broadcasting, and CUDA, you see backpropagation in its purest form: a handful of local derivatives plus the chain rule. The maths is identical at tensor scale — just vectorised.

Part 2

The Value object

Wrapping a number so it remembers how it was made

Value.__init__ — five fields

class Value:
    """ stores a single scalar value and its gradient """

    def __init__(self, data, _children=(), _op=''):
        self.data = data
        self.grad = 0
        # internal variables used for autograd graph construction
        self._backward = lambda: None
        self._prev = set(_children)
        self._op = _op  # the op that produced this node, for debugging / graphviz
.data
the number
The actual scalar value carried forward through the graph
.grad
the derivative
d(output)/d(this node). Starts at 0; filled in during backward()
_prev
children
The set of Value nodes that were combined to produce this one — the graph edges
_backward
closure
A function that applies this node's local derivative to push grad into its children

_op just records which operation produced the node ('+', '*', 'ReLU', …) — purely for visualisation and debugging.

__add__ and __mul__ — local derivatives

def __add__(self, other):
    other = other if isinstance(other, Value) else Value(other)
    out = Value(self.data + other.data, (self, other), '+')

    def _backward():
        self.grad  += out.grad      # d(a+b)/da = 1
        other.grad += out.grad      # d(a+b)/db = 1
    out._backward = _backward
    return out

def __mul__(self, other):
    other = other if isinstance(other, Value) else Value(other)
    out = Value(self.data * other.data, (self, other), '*')

    def _backward():
        self.grad  += other.data * out.grad   # d(a*b)/da = b
        other.grad += self.data  * out.grad   # d(a*b)/db = a
    out._backward = _backward
    return out

The pattern: each operator (1) computes out.data, (2) wires out to its operands via _children, and (3) defines a closure that, given out.grad, distributes gradient to the inputs using the operation's local derivative — the chain rule, one node at a time.

Promoting plain numbers (Value(other)) lets you write x + 1 naturally.

__pow__ and relu — more rules

def __pow__(self, other):
    assert isinstance(other, (int, float)), "only supporting int/float powers"
    out = Value(self.data**other, (self,), f'**{other}')

    def _backward():
        # d(x**n)/dx = n * x**(n-1)
        self.grad += (other * self.data**(other-1)) * out.grad
    out._backward = _backward
    return out

def relu(self):
    out = Value(0 if self.data < 0 else self.data, (self,), 'ReLU')

    def _backward():
        # derivative of ReLU is 1 where active, 0 where clamped
        self.grad += (out.data > 0) * out.grad
    out._backward = _backward
    return out

__pow__ only supports constant exponents — that is enough to express division (a/b = a * b**-1) and squaring for the loss. relu is the single nonlinearity in the canonical engine.

Other ops & the tanh / exp variants

# dunder helpers built from the primitives
def __neg__(self):       return self * -1
def __radd__(self, o):   return self + o
def __sub__(self, o):    return self + (-o)
def __rsub__(self, o):   return o + (-self)
def __rmul__(self, o):   return self * o
def __truediv__(self, o):return self * o**-1
def __rtruediv__(self,o):return o * self**-1

def __repr__(self):
    return f"Value(data={self.data}, grad={self.grad})"
# In the video, tanh / exp are derived the same way:
def tanh(self):
    x = self.data
    t = (math.exp(2*x) - 1)/(math.exp(2*x) + 1)
    out = Value(t, (self,), 'tanh')
    def _backward():
        # d tanh/dx = 1 - tanh(x)**2
        self.grad += (1 - t**2) * out.grad
    out._backward = _backward
    return out

def exp(self):
    out = Value(math.exp(self.data), (self,), 'exp')
    def _backward():
        self.grad += out.data * out.grad  # d e^x = e^x
    out._backward = _backward
    return out

Compose, don't special-case. Because each primitive sets its own _backward, complex expressions like (b - a).relu() or a full tanh neuron just work — gradients flow through automatically.

Part 3

backward()

Reverse-mode autodiff over the whole graph

The whole of backward() — 15 lines

def backward(self):

    # topological order all of the children in the graph
    topo = []
    visited = set()
    def build_topo(v):
        if v not in visited:
            visited.add(v)
            for child in v._prev:
                build_topo(child)
            topo.append(v)
    build_topo(self)

    # go one variable at a time and apply the chain rule to get its gradient
    self.grad = 1
    for v in reversed(topo):
        v._backward()

Three moves: (1) build a topological ordering of the graph by depth-first search, (2) seed the output's gradient to 1.0 (since dL/dL = 1), (3) call each node's _backward() in reverse topological order.

Why topological order & why +=

Topo order guarantees that when we process a node, every node that depends on it has already contributed its share of the gradient. Process in reverse and each out.grad is fully accumulated before it is read.

Why += not =? A node can feed into several downstream nodes (it is used more than once). The multivariable chain rule says those paths' gradients add up. Accumulating with += is exactly this — and it is why zero_grad() must reset grads before each backward pass.

Part 4

Neurons, Layers, MLP

nn.py — a PyTorch-shaped net on top of Value

Module & Neuron

class Module:
    def zero_grad(self):
        for p in self.parameters():
            p.grad = 0
    def parameters(self):
        return []

class Neuron(Module):
    def __init__(self, nin, nonlin=True):
        self.w = [Value(random.uniform(-1,1)) for _ in range(nin)]
        self.b = Value(0)
        self.nonlin = nonlin

    def __call__(self, x):
        # w · x + b, then optional ReLU
        act = sum((wi*xi for wi,xi in zip(self.w, x)), self.b)
        return act.relu() if self.nonlin else act

    def parameters(self):
        return self.w + [self.b]

A Neuron holds one Value weight per input plus a bias. Calling it builds the expression w·x + b — note sum(..., self.b) uses the bias as the start value — then applies ReLU. Every arithmetic op here is a Value op, so the graph is built automatically and is fully differentiable.

Layer & MLP

class Layer(Module):
    def __init__(self, nin, nout, **kwargs):
        self.neurons = [Neuron(nin, **kwargs) for _ in range(nout)]

    def __call__(self, x):
        out = [n(x) for n in self.neurons]
        return out[0] if len(out) == 1 else out

    def parameters(self):
        return [p for n in self.neurons for p in n.parameters()]

class MLP(Module):
    def __init__(self, nin, nouts):
        sz = [nin] + nouts
        self.layers = [Layer(sz[i], sz[i+1], nonlin=i!=len(nouts)-1)
                       for i in range(len(nouts))]

    def __call__(self, x):
        for layer in self.layers:
            x = layer(x)
        return x

    def parameters(self):
        return [p for layer in self.layers for p in layer.parameters()]

A Layer is a list of Neurons; an MLP is a list of Layers chained together. nonlin=i!=len(nouts)-1 makes the final layer linear (no ReLU) so it can output any real value. parameters() flattens every weight and bias for the optimiser.

Building a net

from micrograd.nn import MLP

# 3 inputs → 4 → 4 → 1 output
model = MLP(3, [4, 4, 1])
print(model)
# MLP of [Layer of [ReLUNeuron(3) x4],
#         Layer of [ReLUNeuron(4) x4],
#         Layer of [LinearNeuron(4)]]

x = [2.0, 3.0, -1.0]
y = model(x)          # a single Value
print(y)              # Value(data=..., grad=0)

Part 5

Training loop

Forward, loss, backward, update — repeat

The four-step loop

model = MLP(2, [16, 16, 1])     # 2-layer hidden MLP for the moons dataset

for k in range(100):
    # 1. forward: predictions for every example
    scores = [model(x) for x in inputs]

    # 2. loss: mean-squared error (or svm max-margin in the demo)
    loss = sum((yi - si)**2 for yi, si in zip(targets, scores)) * (1.0/len(scores))

    # 3. backward: zero old grads, then backprop
    model.zero_grad()
    loss.backward()

    # 4. gradient-descent update: nudge each parameter downhill
    learning_rate = 0.1
    for p in model.parameters():
        p.data -= learning_rate * p.grad

    print(k, loss.data)

Notice the order: zero_grad() before backward() (because gradients accumulate with +=), and the update reads p.grad only after backprop has filled it in.

The gradient-descent update

for p in model.parameters():
    p.data -= learning_rate * p.grad

p.grad is the direction in which the loss increases fastest. Subtracting a small multiple of it moves each weight in the direction that decreases the loss. learning_rate controls the step size.

Common bug: forget zero_grad() and gradients from previous steps keep accumulating, sending training haywire. micrograd makes the cause unmistakable — it is the same += from Part 3.

Part 6

micrograd vs PyTorch

Same idea, different scale

Same API shape

# micrograd
from micrograd.engine import Value
from micrograd.nn import MLP

x = [Value(2.0), Value(0.0)]
model = MLP(2, [16, 16, 1])
y = model(x)
loss = (y - target)**2
model.zero_grad()
loss.backward()
for p in model.parameters():
    p.data -= 0.1 * p.grad
# PyTorch
import torch
import torch.nn as nn

x = torch.tensor([2.0, 0.0])
model = nn.Sequential(
    nn.Linear(2,16), nn.ReLU(),
    nn.Linear(16,16), nn.ReLU(),
    nn.Linear(16,1))
y = model(x)
loss = (y - target)**2
model.zero_grad()
loss.backward()
# optimiser.step() does p.data -= lr*p.grad

Look how little changes. backward(), zero_grad(), parameters(), the update rule — micrograd was built to mirror PyTorch so the leap to the real framework is tiny.

Scalars vs tensors

One node holds1 floatmillions of floats
Backwardper-scalar closuresfused tensor kernels

NonlinearitiesReLU (tanh/exp in video)dozens, optimised

Speedslow but clearfast and opaque

Why scalars are slow: a tensor op that PyTorch fuses into one GPU kernel becomes thousands of separate Python objects and closures in micrograd. Illuminating to read, hopeless to scale.

How this scales up

The leap to tensors is mechanical. Replace each scalar local derivative with its matrix/broadcast equivalent: __add__'s "grad flows through unchanged" becomes a broadcasted sum-reduction; __mul__'s "multiply by the other operand" becomes a matrix product with the right transpose. The topological-sort-and-reverse skeleton of backward() is exactly the same in PyTorch's autograd.

Add GPU kernels, operator fusion, mixed precision and a huge op library, and you have a production framework — but the conceptual core is the ~100 lines you just read.

micrograd at a glance

The Value

  • .data — the scalar
  • .grad — the derivative
  • _prev — child nodes
  • _backward — local rule

Operations

  • + · × · ** · ReLU
  • each sets a _backward
  • chain rule, locally
  • composes automatically

backward()

  • topological sort (DFS)
  • seed output grad = 1
  • reverse traversal
  • accumulate with +=

Training

  • forward → loss
  • zero_grad()
  • loss.backward()
  • p.data -= lr·p.grad

Key Takeaways

1

Backpropagation is just the chain rule, applied locally. Each operation knows only its own derivative; the engine stitches them together by walking the graph in reverse.

2

A neural net is one big differentiable expression. Neurons, layers and an MLP are nothing but compositions of Value ops — so a single loss.backward() computes every gradient.

3

Scale, not concept, separates this from PyTorch. Swap scalars for tensors and add GPU kernels; the ~150-line core you just read is the real thing, demystified.
